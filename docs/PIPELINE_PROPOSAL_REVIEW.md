# 对「新闻 → 判质量 → 找评价 → 洗稿」的评估

用户提的形状（2026-09-24）：

> 读到一个新闻，llm 判断质量，质量优，全网搜寻 creators 的评价，之后洗稿，写出自己的东西

结论：**形状是对的**，和公开实践里那条成熟流水线一致，后半段今天已经接上。
但有两处按字面实现会卡死，一处违反本项目自己的规则。下面逐条说，并给出改法。

## 一、「LLM 判断质量」放在第一道，位置错了

一次抓取就是 195 条（2026-09-24 实测，10 个源）。按半小时一轮，一天几千条。
对每一条调 LLM 有两个问题：

1. **贵**，而且贵在最没价值的地方——99% 的条目会被判为不相关。
2. **模型自评不算验收**，CLAUDE.md 明确写了。用它当唯一闸门，等于把把关权交给
   一个没有外部校验的判断。

更重要的是：**有一个免费且更准的质量信号已经在手里，被漏掉了。**

> **creators 谈没谈这件事，本身就是质量信号。**

62 位 donor、12 个轮询账号的语料就在本地。如果一条新闻里的实体，
在观察名单里没有任何人提过，那它对这四个账号就不是故事——不管它多重要。
这个判断是纯本地计算，零调用成本，而且比模型的「质量评分」更贴近产品目标：
这个系统的定位就是「这批 KOL 现在在说什么」。

**改成：**

```
新闻抓取
  → 去重（URL/hash，已有；向量层待建）
  → 聚类成事件
  → 实体命中观察名单？        ← 免费，本地，砍掉绝大多数
  → creators 谈过吗？          ← 免费，本地，这是主质量信号
  → 只对活下来的调 LLM 判断    ← 贵的那一步放在最后
  → 取证、写作
  → 人工审核
```

LLM 那一步不是不要，是**放在最后**，只处理已经通过免费筛选的少数。

## 二、「全网搜寻」做不到，这是硬约束

必须说清楚，因为它决定了产品能承诺什么：

| 想要的 | 实际能拿到的 |
|---|---|
| 全网 creators 的评价 | 12 个轮询账号 + 62 位 donor 语料 + 10 个新闻源 + 3 个视频转写 |

**X 关键词搜索返回 404**（2026-09-24 复测，不是沿用旧记录）。
所以没有办法「搜全网谁在谈这件事」，只能「看我们名单里谁在谈」。

这正是今天刚加闸门拦的那个错误：拿 12 个账号写出「英文社区最近更多在讲」。
样本的性质不是世界的性质。**做不到就不要写成做到了。**

想扩大覆盖，只有三条路，成本递增：

1. **往名单里加账号**（免费）。轮询是按账号的，加人就是加覆盖。
   最直接，也最该先做。
2. **Apify 之类的 X 搜索 actor**（需授权 + 按量付费）。
   当前 Apify MCP 未认证，且 CLAUDE.md 禁止未授权的批量付费调用。
3. **第三方聚合**（如 cryptocurrency.cv，无需 key）。只覆盖 crypto，
   且是二手，provenance 弱于直接轮询。

## 三、「洗稿」这个词对应的动作，本项目有明确规则

CLAUDE.md 写得很具体，不是我加的限制：

- **同语言禁止**：中文源 → 中文稿，不得搬措辞、句式、论证顺序。只能独立重写。
- **跨语言允许**：英文一手信息 → 中文稿，搬的是**信息**不是句子，须注明来源与原语言。
- **跨平台允许**：同样只搬信息，且按目标平台重组。

所以这一步准确的说法不是「洗他的稿」，而是：
**读他的观点 → 形成自己的判断 → 自己写 → 注明是谁的说法。**
允许明确不同意，并说出为什么——这比复述有价值。

今天已接：`live/opinions.py` 把真实原帖（作者、语言、时间、post_id 可查）
送进所有内容线的提示词，并按稿件语言分别声明可搬与不可搬。

## 四、视频：现成资产，接着没用

`evidence_loop/` 里这条链是**跑通过的**：

- `discover_video.py` 用 yt-dlp 公开发现，不用 cookie、不用付费 API
- `transcript_pipeline.py` 按 human_caption → auto_caption → ASR 的阶梯取字幕，
  带时间戳 cue、滚动字幕去重叠（只改分析文本，不动原始 cue）
- `.runtime/models/diarization/` 说话人分离模型在位
- 现有产物：3 个完整转写（35KB / 51KB / 18KB）+ VTT + info.json

**但它和 live 链路是断的。** 这是当前最有价值的闲置资产，原因很具体：

视频是 creators **把推理讲完整**的地方。X 短帖只给结论，视频给中间那几步。
而稿件目前最弱的恰恰是「一句判断怎么从事实推出来」——
用户原话是「写清一句判断是怎么从前面的事实推出来的」。

按 CLAUDE.md，视频主要进**知识 / 推理 / 框架 / 预测 / Evergreen**，
不直接学 X 短帖的 Style/Habit。这条限制和上面的用途正好吻合：
要的就是推理，不是文风。

## 五、建议顺序

1. 新闻源跑几天，攒出真实量级与噪声分布（进行中）
2. 实体命中 + creators 谈论度，作为免费筛选层
3. 向量去重（同一通稿多家转发，hash 抓不住）
4. 聚类成事件
5. LLM 判断只作用于幸存者
6. 视频转写接入 opinions 层
7. 定时器（最后）

第 2 步是投入产出比最高的一步，且不花钱。
