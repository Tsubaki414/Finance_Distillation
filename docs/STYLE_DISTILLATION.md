# 语言蒸馏：做了什么，做到了什么，没做到什么

评估脚本 `ml/style_eval.py`，实现 `live/style.py`。所有数字都是跑出来的，不是估的。

## 度量本身先要站得住

判断「这段文字像谁」用的是 stylometry 特征上的标准化距离。**先验证这个度量能不能认人**：
拿真人帖子逐篇去认作者，**认回自己 65.4%（157/240），随机基线 16.7%**，且最近 donor 的分布是
散开的（michael 61 / xingpt 48 / kovainvest 44 / phyrexni 39 / aleabitoreddit 37 / qinbafrank 11），
没有哪个 donor 是「万物吸引子」。度量可用。

## 改造前的基线

| 指标 | 数值 |
| --- | --- |
| 人机可分辨性 AUC（全部特征） | **1.00** |
| 人机可分辨性 AUC（仅形状特征） | **1.00** |
| 实时链路是否有 language donor | **没有** |

差距最集中的地方，多数由生成模板本身造成：

| 特征 | 真人 | 机器 |
| --- | --- | --- |
| 长论述句占比 | 0.058 | 0.311 |
| 最短四分位句长 | 35.7 字 | 70.8 字 |
| 句长均值 | 56.8 字 | 81.2 字 |
| 短句/碎句率 | 0.166 | 0.000 |
| 以「核心判断」类标签开头 | 从不 | 30% |

## 做了什么

1. **补语料**。英文 donor 原本只有 1–18 篇，建不了区间。用实时采集器深采后
   `beth_kindig` 111 篇、`globalmktobserv` 77 篇、`citrini` 36 篇，够建 p10–p90 区间。
2. **实测风格目标**。`live/style.py` 从每位 donor 的真实帖子算出句长、短句率、长句率、
   第一人称率、开头习惯等的 p10–p90 区间，不是一个点。
3. **写进 prompt 并强制执行**。目标以可执行的话给出（「至少 2 句在 20 字以内」），
   生成后按区间校验，不合格带着具体差距退回重写。**这一步是「蒸馏」与「few-shot 提示」的分界**：
   贴几篇范文进 prompt 不算，测了、给了目标、并且检查了才算。
4. **拆掉压死风格的模板**。原来的「第 1 句给判断、第 2–5 句支撑、共 7–9 句」直接制造了
   模板化开头与整齐长句。证据义务（数字锁死、必须有失效条件）保留，句子形状交回给写手。
5. **给四个账号各指派 language donor**：中文宏观→qinbafrank、中文产业→xingpt、
   英文宏观→globalmktobserv、英文产业→beth_kindig。

## 做到了什么

| 阶段 | AUC（全部特征） | AUC（仅形状） | 指派 donor 进前 3 |
| --- | --- | --- | --- |
| 改造前 | 1.00 | 1.00 | — |
| 加实测目标 + 闸门 | 1.00 | 0.85 | 4/10 |
| 再加厚 exemplar | **0.85** | **0.85** | **5/10** |

被闸门管住的特征确实进了 donor 的区间：句长均值从 81 字降到 34–39 字（qinbafrank 区间
27.7–50.3），长句率归零，开头标签消失。

## 没做到什么

**1. 声音身份没建立。** 指派 donor 排第 1 只有 3/10，且**这 3 篇全部来自已交付链路**
（只贴 exemplar、没有实测目标和闸门）。实时链路 7 篇的名次是 2/3/4/4/5/6/7，
中位数第 4（共 9 位 donor，随机中位数是 5）——**比随机略好，但远不是「像那个人」**。

**2. 仍然一眼可辨。** AUC 0.85 意味着分类器还是能分开。残余差距集中在本地模型不肯产出的东西：

| 特征 | 真人 | 机器 |
| --- | --- | --- |
| 句长标准差 | 25.6 | 7.8 |
| 短句率 | 0.165 | 0.000 |
| 引号使用 | 0.0065 | 0.000 |
| cashtag 密度 | 0.0034 | 0.000 |
| 括号使用 | 0.0036 | 0.0002 |

**3. 一个反直觉的结果值得记下**：贴长 exemplar 对声音的作用**大于**给数值区间。
加厚 exemplar 把全特征 AUC 从 1.0 压到 0.85，而只加数值目标时全特征 AUC 纹丝不动。

## 一处主动放宽，写明理由

`sentence_std`（句长变化度）**测量并报告，但不作硬闸门**，两个理由都要成立才拿掉：

1. 本地模型在 4 次尝试、3 种写法（含「至少 2 句 15 字以内、至少 1 句 80 字以上」这种可数配比）
   下都拒绝变化句长，返回十句 33–47 字。这是模型能力边界，不是 prompt 问题。
2. 它属于长度类特征，而长度在「迁移」度量里是被我刻意排除的——理由是长度由体裁决定。
   用它当硬闸门等于逼一篇分析稿去模仿 X 短帖的体裁。

这个数字仍出现在每一次 `style_check` 和 `ml/style_eval.py` 里，没有被藏起来。

## 下一步（按预期收益排序）

1. **换写作模型**。句长变化、碎句、引号、括号这几项本地 4B 模型不产出，换更强的模型是
   单点收益最大的改动，其余机制不用动
2. **按 donor 建 few-shot 库**，检索与当前题材最接近的该作者帖子，而不是随机抽 6 篇
3. **补齐英文 donor 语料**（`citrini` 36 篇、`ericjackson`/`rjccapital`/`tradexwhisperer` 仍不足 25 篇）
4. 盲测：让真人在混合样本里挑出机器写的，与 AUC 对照

# 更正：「英文做不到」是我的度量错了

上一节说英文迁移「几乎等于随机」。**这个结论是错的**，来自一个不该用的指标。

## 错在哪

我用的是**闭集排名**：在 36 位 donor 里，生成稿离被指派的那位排第几。问题在于
`globalmktobserv` 处在风格拥挤区（密集度第 8/36），周围 WarrenPies、RaoulGMI、TaviCosta
都是同质的英文宏观评论者。**对着一个不独特的目标问「排第几」，考的是这位 donor 有多特别，
不是模仿有多像。**

## 换成验证式度量

问题应该是「这段文字看起来像不像出自这位作者」，而不是「它比其他 35 位更像谁」。
所以改测：生成稿到该 donor 的距离，落在**这位 donor 自己帖子距离分布**的哪个百分位。

先验证这个度量能区分人：

| donor | 该作者自己的帖子落在范围内(≤95%) | **别的作者**的帖子落在范围内 |
| --- | --- | --- |
| qinbafrank | 100%（中位 42%） | **5%** |
| beth_kindig | 98%（中位 45%） | **23%** |
| globalmktobserv | 98%（中位 49%） | **11%** |
| xingpt | 92%（中位 57%） | **6%** |

别人的帖子有 77–95% 会被判在范围外。度量有效。

## 真实结果

| 账号 | donor | 闭集排名 | 落在该作者自身分布 |
| --- | --- | --- | --- |
| 中文产业 | xingpt | 3 | **39.6%** |
| 中文宏观 | qinbafrank | 5 | **49.7%** |
| 中文宏观 | qinbafrank | 4 | **53.8%** |
| 英文产业 | beth_kindig | 5 | **55.0%** |
| 英文宏观 | globalmktobserv | 25 | **74.0%** |
| 英文产业 | beth_kindig | 14 | **78.4%** |
| 英文宏观 | globalmktobserv | 28 | 100%（范围外） |

**7 篇里 6 篇落在被指派作者的常写范围内，中英文都是。**几篇中文稿比该作者的中位数还典型。

反过来，**闭集排名第 1 的三篇旧稿都在 100 百分位**——它们「排第一」只是因为离 phyrexni
比离别人近，实际上不像 phyrexni 写的任何东西。闭集排名在两个方向上都误导了。

## 顺带修好的两件事（这才是英文变好的原因）

1. **英文槽位是整段从句，中文槽位是光秃秃的数字。** 同一份事实包，英文渲染出
   `'inflation expectations have risen to around 2 percent'`（模型必须原样嵌入，四个槽位就是
   四个长从句），中文渲染出 `'4000 亿日元'`（连主语都没有）。英文的均匀长句、零碎句，
   是这个渲染造成的，不是模型不会写英文。
2. **改用模型给事实命名。** 正则从上下文里截主语，在财报上可用，在连续行文上产出
   `"in South Korea Chart 8 units"` 这种垃圾。改为让模型只做一件事——读原句、说出这个数字
   衡量什么，输出 2–6 字的名词短语，**含数字的标签一律拒绝**。数字、量级、单位仍全部由代码
   渲染，这条线没有让步。`live/label_facts.py`

   效果：`国债购买量削减 4000 亿日元` / `JGB purchase reduction 400 billion yen`。
   过闸率同时从 5/8 升到 7/8。

## 借鉴的现成实现

- **Burrows' Delta**（`fastdatascience/faststylometry`）：作者归属的标准方法，已实现在
  `ml/style_eval.py`。**只借方法不装包**——该包锁 numpy 1.26，会破坏本项目冻结环境。
  36 位作者下认回率 12.0%（随机 2.8%），与我那套特征指标量级一致，两个独立度量互相印证。
- 搜到的其余高星「style transfer」几乎全是图像风格迁移，与本任务无关。

## 仍然成立的问题

人机可分辨性 **AUC 0.95** 没有改善。这与「像不像那位作者」是两个问题：稿子在可测的写作习惯上
已经落进 donor 的区间，但整体上仍能被分类器识别为机器所写。残余差距仍集中在句长变化、碎句、
引号与括号——本地 4B 模型不产出这些。**换写作模型仍是下一步收益最大的改动**，但它现在
只针对「像人」这一项，不再是「英文做不到」。

# 盲测：18 篇混合样本，强模型判别（2026-09-12）

没有可用的外部 LLM API key，因此最强评委是助手本人（Opus）。它也建了这条流水线，所以必须盲：
`ml/blind_set.py` 生成打乱的混合集与另存的答案表，判断先写进
`ml/blind/judgements.json`，再读 `answers.json`。

为公平起见，真人帖按**长度匹配**且**筛掉纯反应式短帖**——拿一句话行情评论对八句分析稿，
测的是体裁识别，不是质量。

## 结果：18/18，100%

9 篇机器稿、9 篇真人帖，**全部判对，无一犹豫**。这就是「质量怎么样」的答案：
风格指标（AUC 0.8–0.9）说明它进了 donor 的区间，但**一个强读者仍能一眼分辨**。

判别依据几乎全是同一类——机器稿每句一个事实、长度均匀、没有论证的推进；
真人帖有离题、有自造比喻、有指涉自己此前的立场、有赞助声明和短链。

## 更重要的：盲读抓出 5 处所有闸门都放行的缺陷

| 缺陷 | 实例 | 闸门为何没抓到 |
| --- | --- | --- |
| 遮蔽占位符进正文 | `"Buy Japanese Yen (JPY) $5[figure withheld] bil."` | 不是错误数字 |
| prompt 规则原句进正文 | `A threshold in the invalidation sentence is the only figure allowed outside the table.` | 不是错误数字 |
| 骨架小标题当正文 | 「价格与工时这条线显示…」（三篇中文稿全中） | 不是错误数字 |
| 末句截断 | `失效条件：若私人非农平均周工时变化 0.` | 不是错误数字 |
| 系统编号进正文 | `L01 Yen intervention 98 billion dollars` | 曾被当作表外数字误判，而非识别为编号 |

**9 篇已标记 `ready_for_queue` 的稿子里有 5 篇含泄漏。**数值审计看不见它们，因为没有一个是
数字错误——那是机器的脚手架露了出来，属于另一类失败，需要另一道闸门。

## 修法：既堵根因也加闸门

1. 遮蔽标记 `[figure withheld]` / `〔数字略〕` 改为 `a figure` / `某个数值`——
   **即使被抄走也是一句能看的话**，同时仍被闸门拦下
2. 已交付链路的十条骨架从「小标题」改写为「写作要求」，并明确「这些说法本身不要写进正文」
3. 新增 `content/leak_check.py`：遮蔽标记、指令原句、骨架小标题、系统编号、截断结尾，
   五类全部 blocking，双语反馈可执行；接进两条链路的重试循环
4. 13 条测试逐条覆盖，每条都来自这次盲读的真实实例

**修后回放：10 篇稿件，含泄漏 0 篇。**

## 诚实的结论

- 事实正确性：站得住（66/66 可回溯、S1 回归 5/5、205 测试通过）
- 风格迁移：站得住（8/10 落在被指派作者的常写范围内）
- **像不像真人写的：不像。强读者 18/18 分得开。**

风格指标进了区间，不等于读起来像人。两者都要测，而这次是盲读——不是指标——找到了
那 5 个会让人丢脸的缺陷。**读稿仍然是不可替代的一道。**

# 借鉴 GitHub：AI 写作痕迹检测（2026-09-12）

搜到的「humanizer」类 skill 多数目标是**绕过 GPTZero/Turnitin**，靠同义词替换和隐藏字符——
那会直接破坏事实完整性，与本项目相反，不采用。

真正对路的是 `skyf0xx/hedgehog-core-copywriting-prose-engineering`：它不是绕过检测，
而是**用代码判 AI 写作痕迹的质量闸门**，架构与本项目一致（「模型写、规则判、循环修」），
连 X 的 280 字符按 CJK 计法都对上了。

## 借了什么

`rules/tells.mjs` 的禁用词表、套话表、否定式强调、三连排比、hedge 堆叠、系动词回避，
以及最重要的设计原则：**频率而非出现**——一次三连排比是正常散文，多次才是机器痕迹。

## 但先验证，再启用

那份清单是给**英文营销文案**写的。直接搬过来会拿别人的语料去卡金融写作。
`ml/tell_validate.py` 在 3,322 篇真人帖上逐条测：

| 规则 | 真人/千词 | 机器/千词 | 结论 |
| --- | --- | --- | --- |
| 系动词回避（中） | 0.07 | 0.57 | ✅ 7.8 倍，启用 |
| 禁用词（英） | 2.6% 文档 | 25% 文档 | ✅ 启用 |
| 三连排比（中） | **1.76** | 0.00 | ❌ **真人用得更多** |
| 套话（中） | 2.8% | 0.0% | ❌ 真人更多 |
| 否定式强调 / hedge 堆叠 | 0 | 0 | ❌ 从不触发 |

**八条里只有两条转移得过来。**其余保留在文件里、每次仍然测量，但停用，并把停用它的那个数字
写在代码注释里——避免以后有人"顺手打开"，反而拦掉正要模仿的真人。

## 自己加的一条，效果最大

盲读时我给出的判据是「每句一个事实、没有论证推进」。这是可量化的：

| | 带数字的句子占比（中位） |
| --- | --- |
| 中文真人 | **42%** |
| 中文机器 | **82%** |
| 英文真人 | **33%** |
| 英文机器 | **86%** |

根因是槽位机制——每个槽位变成一句话，流水线在奖励塞数字。
新增 `every_sentence_carries_a_figure` 闸门，上限取真人 p90（中 0.78 / 英 0.67）；
低于不罚，真人本来就有大量无数字段落。

**当时在库的 10 篇里，9 篇不过这道闸门。**

## 效果

中文稿密度降到 57–75%，读起来出现了真正的推进句：

> 亚马逊非运营税前其他收入高达 534 亿美元，主要来自对 Anthropic 的投资。
