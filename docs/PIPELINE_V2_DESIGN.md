# Pipeline v2：不再从零写，改成从一篇高质量原文出发

> **2026-09-27 更新。** 用户的指示是「推翻你之前做的所有，只是让模型读然后洗稿重写；
> 而不是提取关键词、模仿语言等绕一大圈」。下面第 0 节是拆除清单，
> 源清单已落到 `live/research_sources.json`。

## 〇、拆掉什么

我建的那套的共同问题：**它们都在回避一件简单的事——让模型读一篇好文章，写自己的版本。**
每一层都在把「文章」拆成特征，然后试图用特征把文章拼回去。

### 删

| 模块 | 它在做什么 | 为什么是绕路 |
|---|---|---|
| `live/style.py` | 句长变异、数字密度的 donor 百分位区间 | 用统计量描述风格，再要求模型命中区间。模型读五段原文就够了 |
| `live/habit.py` | 发帖节奏、活跃/沉默天数 | 从没进过提示词 |
| `live/terms.py` | 用词统计 | 同上 |
| `live/positions.py` | 立场与预测台账 | 想法对，但服务的是 v1 的「从零写」 |
| `live/label_facts.py` | 用模型给每个数字命名指标 | **典型的提取关键词。** 原文里那个数字本来就有上下文 |
| `live/render_slots.py` | 把数字渲染成 slot 表 | 把文章拆成数字，再要求模型把数字放回句子里。数字密度高和「指标名+数字+逗号」8/8 都是它造的 |
| `evidence_loop/experiments/roles_v2.json` 的角色加权 | knowledge/reasoning/language/habit 分别指派 donor | 五个角色里四个在三个人设间完全相同，本来就是名义上的 |
| `ml/sentence_dataset.py` | 「给数字造句」的监督数据 | 训练路线已判定不可行 |
| `ml/train_sentence_lora.py` | LoRA 训练 | 同上 |
| `ml/dequantize_base.py` | 反量化 | 同上 |
| `ml/sentence_eval.py` | label-before-number 诊断 | 它诊断的是 slot 机制造成的缺陷；slot 没了，它也没意义 |
| 提示词里的「6 到 10 句」 | 长度强制 | 真人 11.2% 的帖子 ≤3 句，我们 0% |
| 提示词里的四要素强制 | 结构强制 | 真人 5.2%，我们 59.4%。**这是最主要的机器味来源** |
| `content/tells.py` 的词表部分 | 机器味词表 | 实测：我凭空想的词，真人在用，模型不用。`abstract_inflation` 拦 26 条真人、抓我们 0 条 |

### 留（只留真的在干活的）

| 模块 | 为什么留 |
|---|---|
| `live/write.audit` 数值审计 | 值+单位必须对得上原文。这是核对不是判断，v2 里更重要——洗稿最容易错的就是数字 |
| `content/originality.py` | 同语言搬运检测。v2 里源就是别人的文章，这条从「以防万一」变成「核心约束」 |
| `content/gate_calibration.py` | 误伤预算制度。**不许在不知道误伤率的情况下新增闸门** |
| `ml/human_review.py` | 唯一验收 |
| `ml/budget.py` | 硬上限 |
| `live/news.py` 的时效校验 | 今天又抓到 4 个假活源（SemiAnalysis、The Diff、FedGuy、Macro Compass），全部 HTTP 200 |
| `live/opinions.py` | KOL 观点。v2 里它从「素材」变成「对照面」——原文说 A，中文圈在说 B |
| `live/cluster.py` | 去重聚类。多个源报同一件事时仍然需要 |
| `evidence_loop/` 视频转写 | 跨平台路径，规则允许，且一直没接 |

### v2 的全部步骤

```
1. 取源       research_sources.json 里的 feed → 列表
2. 取正文     RSS 只给摘要，洗稿要全文
3. 挑         哪篇值得写？哪个人设？——一次模型调用，允许答「都不值得」
4. 读+写      把全文给模型，连同人设和那几条 KOL 观点，让它写自己的一篇
5. 核         数字对不对、是不是逐句直译、来源注明没有
6. 人审
```

**没有特征提取，没有风格区间，没有 slot 表，没有模板。**



2026-09-25。**这是设计，还没建。** v1 的实测状态在 `docs/PIPELINE_AS_BUILT.md`。

## 为什么换

同事的原话：

> 就是从 0 组织一篇文章去 ai 味是很难的
> 但是洗稿是简单的
> 换个思路，没必要自己从零开始写

这个判断有数据支持，而且数据是我们自己的：

| | 真人中文帖（1,376） | v1 从零写的（32） |
|---|---|---|
| 四要素齐备（判断+数字+反面+失效条件） | **5.2%** | **59.4%** |
| 句数 ≤3 | 11.2% | **0%** |
| 字数 p10 / p90 | 154 / 1160（7.5 倍） | 255 / 458（1.8 倍） |

**从零写，结构就得由提示词规定；一规定，每篇就长一个样。**
59.4% vs 5.2% 是 11 倍差距，不是调措辞能补的——它是架构决定的。

三轮人工盲测检出率都是 1.0，其中一轮的 groundedness 是 5.00/5、naturalness 是 0.17/5。
**v1 把全部复杂度花在「正确」上，而读者反应的是另一个轴。**

洗稿的机制优势很具体：**结构是从人那里继承的，不用编。**
一篇真人写的研究，自带角度、论证顺序、详略分配、该在哪里停。
这些恰好是 LLM 最难伪造、而我们一直在用模板替代的东西。

## 一条必须先说清楚的约束

`CLAUDE.md` 的搬运规则：

- **同语言禁止**：中文源→中文稿、英文源→英文稿，不得搬运措辞、句式、**论证顺序或结构**
- **跨语言允许**：搬的是信息与事实，不是句子；每句仍须自己写，注明来源与原语言，
  **不得逐句直译冒充原创**
- **跨平台允许**：视频字幕→贴文等，同样只搬信息并按目标平台重新组织

同事说的「互相洗洗抄抄」是同语言的，被这条规则排除。
**但跨语言那条路更强，不是退而求其次：**

1. **结构从英文原文继承，中文全部重写。** 人写的骨架 + 不构成同语言抄袭，两头占。
2. **中文读者读不到 clausaasholm、The Overshoot 这些。** 这是真实信息差。
3. 它本来就是六条内容线里的 Cross-language Information Gap。

规则是用户定的，可以改。改之前需要知道改的是什么。

## v2 的形状

```
v1:  事件 → 一手文件 → 40 个数字 → slot 表 → 按四要素模板从零写 → 7 道闸

v2:  高质量原文 → 它自带角度/结构/论点/证据
       → persona 读它，决定态度：同意 / 反驳 / 延伸 / 本地化 / 不写
       → 用目标语言写自己的那一篇
       → 核验：数字对得上原文、没有逐句直译、来源已注明
```

两个根本差别：

**「这篇值不值得写」由选源解决，不再由生成解决。**
v1 靠 `opportunities.py` 打分从事件里挑，然后强行写成完整分析。
v2 里，一篇被选中的原文已经证明了它值得写——有人花时间写了它。

**结构由原文决定，不再由模板决定。**
原文三段，我们就三段；原文只讲一件事，我们就只讲一件事。
`6 到 10 句` 和四要素强制**全部删除**。

## 新增与删除

### 删除

| v1 的东西 | 为什么删 |
|---|---|
| 「写 6 到 10 句」 | 真人 11.2% 的帖子 ≤3 句，我们 0%。长度应当跟原文 |
| 四要素强制（判断/数字/反面/失效条件） | 真人 5.2%，我们 59.4%。结构应当跟原文 |
| slot 表作为**写作输入** | 数字先渲染再要求放进句子，是数字密度高与「指标名+数字+逗号」8/8 出现的共同原因。**审计保留**——写完再核对足够 |
| `opportunities.py` 决定写什么 | 降级为排序，不再是唯一入口。选源本身已经是筛选 |

### 新增：一道 v1 不需要而 v2 必须有的闸门

**逐句直译检测。**

跨语言允许搬信息，禁止「逐句直译冒充原创」。
现有的 `originality.py` 比的是字符重合，跨语言天然为零，**完全抓不到这件事**。

做法：把原文句子和成稿句子分别向量化（本机多语言模型，已有，零成本），
算对齐矩阵。如果成稿里绝大多数句子都能在原文中找到高相似度、
且**顺序基本一致**的对应句，那就是翻译，不是重写。

判据是两个而不是一个：
- **对齐率**：多少比例的成稿句子有高相似原文句
- **顺序相关**：对齐位置的序号相关性

只看相似度会误伤正常的「同一主题」；加上顺序才能把翻译和独立写作分开。
阈值必须像 `cluster.py` 那样**从实测分布里读**，不能拍——
拿真人写的中英对照（同一事件、不同作者）做负样本，
拿机器直译做正样本，看两者分布在哪里分开。

### 保留

- 数字审计（值+单位必须对得上原文）——确定性，不交给模型
- `gate_calibration.py` 的误伤预算制度：**不许在不知道误伤率的情况下新增闸门**
- 人工盲测是唯一验收
- 留痕：每篇稿必须能回到原文 URL、原文 hash、用了哪几句的哪几个数字

## 实施顺序

1. **接源。** `live/research.py`，形状照搬 `live/news.py`（增量、水位、时间戳校验），
   按 persona 分组。先只接英文，因为它们有 RSS，今天就能跑。
2. **抓全文。** RSS 只给摘要，洗稿需要正文。Substack 的文章页可直接取。
3. **持有态度那一步。** 提示词的核心从「写一篇分析」改成
   「你读了这篇，你同意吗，你要补什么，还是你不想写」。允许输出「不写」。
4. **建直译检测**，用实测分布定阈值。
5. **A/B**：同一批原文，v1 方式（从零写）对 v2 方式（从原文出发），
   混进真人帖盲测。**这是唯一能回答「洗稿是不是真的更像人」的实验。**
6. 中文源走 Apify（公众号 + 雪球），服务英文账号。
7. 视频转写接入——`evidence_loop/` 那条链已经跑通但和 live 断开，
   而视频→文字是跨平台，规则允许，且视频是把推理讲完整的地方。

前 5 步不需要新授权，成本以现有预算完全覆盖。
第 6 步要花 Apify 额度（目前剩约 $445）。

## 这个设计可能错在哪

写在前面，免得事后找理由：

- **洗稿可能只是把机器味换个位置。** 继承结构确实解决「每篇一样长」，
  但句子仍然是模型写的。如果盲测还是 8/8，说明问题不在结构在句子，
  那 v2 也白做——所以第 5 步的 A/B 必须真做，不能跳。
- **选源会变成新的瓶颈。** v1 的瓶颈是「写什么」，v2 的瓶颈变成「读哪篇」。
  如果每天只有 2 篇值得写的原文，四个账号就不够分。
- **跨语言的量不够。** 英文研究源每天更新有限，撑不起日更。
  这可能意味着账号的节奏要跟着源走，而不是反过来——
  这未必是坏事，真人也不是每天都有话说。
